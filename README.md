# Практическая работа №2. Вариант 12

Визуализатор графа зависимостей пакетов Ubuntu APT. Python 3.10+, только стандартная библиотека для получения и анализа зависимостей. `apt`, `pip` и библиотеки анализа пакетов не используются.

## Быстрый старт

```console
python -m aptgraph --config config.csv
python -m unittest discover -s tests -v
```

На Windows можно использовать `run.bat --config config.csv`.

Если Python не установлен, установите Python 3.10+ и включите добавление в PATH. Для проверки в текущем окружении использован переносимый интерпретатор `C:\Users\User\AppData\Local\Temp\opencode\python313\python.exe`.

## Конфигурация

CSV в UTF-8, две колонки `key,value`:

```csv
key,value
package,A
repository,examples/repository.json
test_mode,true
output,output/A.png
filter,
```

| Параметр | Назначение |
|---|---|
| package | Имя пакета; в тестовом режиме только большие латинские буквы |
| repository | Путь к тестовому JSON или HTTP(S) URL индекса APT `Packages`, `Packages.gz`, `Packages.xz` |
| test_mode | true/false (также 1/0, да/нет) |
| output | Путь к выходному PNG |
| filter | Подстрока имени исключаемого пакета; пустая строка отключает фильтр |

Локальные пути разрешаются относительно CSV, а не текущего каталога. Неверный CSV, дубликаты и неизвестные ключи, отсутствие обязательных параметров, неверные имена, режим и расширение PNG диагностируются с кодом выхода 1. Ошибки чтения/сети и отсутствие пакета также обрабатываются.

## Пять этапов

```console
python -m aptgraph --stage config
python -m aptgraph --stage data
python -m aptgraph --stage graph
python -m aptgraph --stage reverse
python -m aptgraph --stage visualize
```

- `config`: параметры в виде ключ=значение.
- `data`: прямые зависимости.
- `graph`: рекурсивный DFS, включая транзитивные зависимости; циклические ребра и отсутствующие метаданные выводятся отдельно.
- `reverse`: прямые и транзитивные обратные зависимости **по всему загруженному индексу**, используя тот же DFS на обращенном графе.
- `visualize` / `all` (по умолчанию): Mermaid `.mmd` и PNG.

Исключенные пакеты не включаются в граф и не обходятся. Если фильтр исключил корень, результат — пустой граф. Самозацикливания и общие зависимости не вызывают бесконечной рекурсии. Очень глубокий граф ограничен глубиной стека Python; переполнение диагностируется.

## Тестовый репозиторий

Формат JSON: объект `имя: [зависимости]`. Имена только A–Z. В `examples/repository.json` имеются:

- ромб `A → B,C; B → D; C → D,E`;
- обратные зависимости `Y → X → A`;
- цикл `F → G → H → F`;
- самозависимость `LOOP → LOOP`.

```console
python -m aptgraph --config examples/demo.csv --stage all
python -m aptgraph --config examples/cycle.csv --stage all
python -m aptgraph --config examples/filter.csv --stage all
python -m aptgraph --config examples/demo.csv --stage reverse
```

Три конфигурации показывают два разных корня и фильтрацию. Для третьего **различного пакета**, требуемого этапом 5, используйте `examples/reverse-demo.csv` (корень X).

## Настоящий репозиторий Ubuntu

Пример приведен в `examples/ubuntu.csv`. URL должен вести непосредственно на индекс, а не на HTML-каталог репозитория:

```text
https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz
```

```console
python -m aptgraph --config examples/ubuntu.csv --stage data
python -m aptgraph --config examples/ubuntu.csv --stage visualize
```

Поддерживаются `Depends`, `Pre-Depends`, переносы строк, сжатие gzip/xz, ограничения версий (удаляются), архитектурные квалификаторы и виртуальные `Provides`. Для альтернатив `a | b` выбирается первый реальный пакет из загруженного индекса, затем первый провайдер; если ни одного нет — первое имя, отмечаемое как отсутствующее. Это визуализация **одного снимка метаданных**, а не полноценный решатель APT: ограничения версий не решаются, состояние установленной системы не учитывается, индексы других компонентов и архитектур автоматически не подгружаются. Рекомендуется использовать один индекс без повторов версий; при повторах выбирается последняя запись.

## Визуализация

Mermaid создается самим приложением. Для PNG:

1. При наличии команды `mmdc` используется установленный Mermaid CLI.
2. Иначе граф отправляется публичному сервису **https://kroki.io/**. Нужен интернет; не передавайте конфиденциальные названия пакетов. Метаданные зависимостей сервис не собирает: он только рисует готовый граф.

Флаг `--offline` запрещает обращение к Kroki и требует `mmdc`. При ошибке рендеринга `.mmd` сохраняется, PNG не подменяется фиктивным изображением.

## Сравнение со штатными инструментами

В Ubuntu для того же выпуска/архитектуры:

```console
apt-cache depends hello
apt-cache depends --recurse hello
apt-cache rdepends hello
apt-cache dotty hello > hello.dot
```

`dotty` формирует DOT, а наша программа — Mermaid. APT может показать больше ребер: он использует несколько компонентов, установленное состояние, альтернативы, `Recommends` и виртуальные узлы. Здесь используются только обязательные `Depends`/`Pre-Depends`, выбирается одна альтернатива, виртуальные имена разрешаются к провайдеру. Порядок узлов и оформление не должны совпадать. В текущем Windows-окружении APT отсутствует, поэтому фактическое сравнение со штатным APT не заявляется выполненным: эти команды необходимо выполнить в Ubuntu/WSL и приложить вывод к отчету.

## Структура

- `aptgraph/config.py` — конфигурация и валидация;
- `aptgraph/repository.py` — загрузка и собственный парсер APT;
- `aptgraph/graph.py` — рекурсивный DFS и обратный граф;
- `aptgraph/render.py` — Mermaid и PNG;
- `aptgraph/__main__.py` — CLI;
- `tests/` — автоматические проверки;
- `examples/` — конфигурации и тестовые данные.

Папка исходников оформлена как Python-пакет `aptgraph`, а не `src`: запуск не требует установки проекта. Наличие `.gitignore`, `tests`, `run.bat` и этого README соответствует общим требованиям оформления. Тестовые PNG и скачанные инструменты в Git не добавляются.
